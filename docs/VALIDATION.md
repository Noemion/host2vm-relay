# 验证范围与复现

本版本以 GitHub Actions 对应提交的结果为准，检查失败会阻止正式 Release。所有证据保存在 `artifacts/checks/`，不会读取真实用户配置或操作公司内网。

## Windows

- 实际 C# 编译、x64/x86 发布程序自检，x64/x86/ARM64 自包含打包。
- DPAPI、配置迁移与冲突备份、定位文件不可用/损坏/写入失败防护。
- v1/v2 旧脚本增量升级、用户区保留、托管区修改拒绝、原 TUN 字段与 Mieru UDP 保留，执行真实 C# 生成的 JS。
- 五个页面、脚本窗口、字段展开、规则与日志状态；100/125/150/175/200 的消息注入回归及 native 100 检查。96 DPI 冒充 native 200 的负例必须返回 BLOCKED。
- 应用 ICO 与独立安装器 ICO；实际 EXE 多尺寸图标提取、Shell 小/大图标与参考资产比较。
- 生产 SOCKS/UDP 代码的本机 TCP/UDP 套接字收发、空数据报、二进制负载、会话健康和子进程异常退出。测试 Python 是夹具，不是 Windows 应用运行依赖。

## Linux 隔离网络

实际使用 Mihomo TUN、SSH.NET 和生产 UDP 组件。普通客户端访问原地址和端口，没有 SOCKS 设置。记录宿主、虚拟机和仅虚拟机可达服务的不同响应，覆盖 TCP/UDP、现有企业 DNS 可解析的名字、空数据报、并发会话、仅 UDP 失效、虚拟机网络断开/恢复，以及应用被终止但规则残留后的原策略回退。

仅 VM hosts 存在的 UDP 名称是明确的 DNS 前置条件限制；测试记录这个差异，不把预期解析失败当作已经支持远端 DNS。UDP helper 自身的 IPv6、本地协议和非法数据报检查另行执行。

## 尚不能由以上结果证明

真实 Windows Clash TUN 的整条链路、用户公司的实际 UDP 服务和 DNS、长期大吞吐 QUIC/音视频、物理高 DPI 多屏切换、ARM64 实机、高对比度主题，以及浏览器下载列表是否展示 per-file EXE 图标。资源提取和 Shell 成功也不表示浏览器必须采用同一个图标。

网络逻辑中自动回退意味着不改客户端地址和代理设置，不意味着已建立的连接永不重试。UDP 通过 SSH/TCP 承载，并非未经封装的 UDP 隧道。
