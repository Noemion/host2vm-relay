# UDP 与宿主机自动回退

## 使用方式

在“连接”页保持“透明转发 UDP”开启，连接虚拟机。在“Clash 接入”中合并已有完整脚本，复制新结果到当前订阅并应用。原客户端继续访问原来的域名、IP、端口；不为每个应用单独设置代理，不逐个映射 UDP 服务端口。现有 Mieru 节点的 `udp = true` 继续保留，未匹配的流量使用原来的分流规则。

远端要求 Linux／兼容 POSIX shell 的 SSH 环境、允许执行命令和 TCP 转发，且 `python3` 可用。应用通过已校验主机指纹的 SSH 会话在内存启动 Python 标准库组件，不安装系统服务、不使用 root、不另开虚拟机监听端口。关闭 SSH 会话或长期没有控制输入时组件退出。Windows 客户端无需安装 Python。

支持单播 UDP 请求与响应、IPv4／IPv6 目标、空数据报和并发会话。暂不支持广播、组播、SOCKS 分片重组或基于局域网广播的自动发现。数据报最大负载 65507 字节；会话与队列有明确上限，过载按 UDP 语义丢弃。客户端到虚拟机这段采用 SSH/TCP 承载，丢包时会受 TCP 队头阻塞影响，不承诺与原生直连 UDP 相同的时延或吞吐。

## 域名解析是独立的前置条件

Mihomo 的 SOCKS5 UDP 出站在发送前会使用 Clash 的 DNS 解析目标域名。此版本保持原有 nameserver 和 nameserver-policy，不擅自改成公网 DNS。因此，内网 UDP 域名必须能由当前 Clash DNS（例如企业 DNS）解析。仅写在虚拟机 `/etc/hosts` 中、宿主机/Clash DNS 完全无法解析的名字，不会自动获得 UDP 解析能力；这种名字可能 TCP 能用而 UDP 失败。

这是已识别且单独验收的限制，不以修改客户端目的 IP、关闭 QUIC 或强制 TCP 冒充解决。需要在现有 Clash DNS 配置中提供适当的内网解析能力；应用仍保持原访问地址。当前版本没有自动复制虚拟机 hosts 文件或把全部 DNS 强制送往虚拟机。辅助组件本身能处理 SOCKS 域名帧，但不能绕过 Mihomo 在 UDP 帧发出之前的解析要求。

## 回退和恢复

TCP 和 UDP 独立检测。SSH 通道失效时两者回退；只有 UDP 组件不可用时，UDP 回退，TCP 仍优先经过虚拟机。关闭 UDP 选项只停用 UDP 接管。用户主动断开后不自动重连；启用自动重连时，异常失联会定期重试。

生成器创建两个 fallback 组，分别检测专用健康地址 `/tcp` 与 `/udp`。组成员顺序为 `PASS`、`Host2VMRelay`：PASS 的健康测试失败，而真正可用的中继返回 204；全部不可用时，组退到 PASS，继续匹配原有规则，而不是强制 DIRECT。专用地址由本机 SOCKS 服务内部处理，不向公网发送健康请求。UDP 检测还包括虚拟机内真实 UDP 套接字的 nonce 收发，不仅检查 SSH 的 IsConnected。

规则文件按协议分别启用和停用，健康组为应用异常退出后可能残留的活动规则提供另一层回退。切换需要检测和 Clash 更新周期，已有 TCP 连接或 UDP 会话可能需要客户端重试，不能声称零丢包或既有会话无缝迁移。回退也不能使本来只在虚拟机网络中可达的服务凭空在宿主机可达。

界面、托盘和日志提示路径变化，同一状态不反复弹出阻塞窗口。界面显示的是中继与规则同步状态，不是 Clash 核心已确认全部会话完成切换。

## 维护与验收

生产代码：`UdpTunnel.cs`、`RelaySocksServer.cs`、`udp_bridge.py`、`MainForm.Networking.cs`。Linux 网络验收复用生产传输代码，创建独立网络命名空间、固定指纹 SSH 服务、真实 Mihomo TUN 和普通 socket 客户端。同一服务地址在宿主与虚拟机返回不同标识，可判断真实出口。检查 IP、现有 DNS 可解析的名字、仅虚拟机可达的地址、并发、空包、UDP 独立失效、断网恢复与进程被终止后的原路径回退。VM-only hosts 名称属于已知 DNS 限制而不是通过项。

Windows 本机传输检查使用实际 Windows TCP/UDP 套接字、生产 SOCKS 入口及独立的 Python 测试进程；它不等于 Windows TUN + 用户公司内网的全链路实测。真实 Windows Clash 版本、企业 DNS、防火墙及具体业务协议仍应在部署环境验证。
