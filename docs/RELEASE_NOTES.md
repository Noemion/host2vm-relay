# Host2VMRelay v0.6.6

本版修复 VMware NAT 网络下的转发循环，避免虚拟机的 VPN 接入请求被再次送回虚拟机。

## 界面修复

- 修复首次进入页面时，说明文字过早换行、卡片高度过大和出现多余留白的问题。文字按当前可用宽度排版。
- 改写设置页的配置目录说明，明确实际存储位置可以调整，Clash 规则文件单独管理。
- 增加首次进入页面的布局检查，避免重复刷新掩盖初始布局错误。

## 连接修复

- 生成的 TCP、UDP 规则排除 VMware NAT 进程 `vmnat.exe`，让虚拟机流量继续匹配 Clash 原有规则。
- 排除来源为所填虚拟机地址的请求，防止保留来源地址的流量再次进入中继。
- 宿主机访问同一域名时，仍按本软件规则转发，无需删除整个域名后缀。
- Clash 关闭进程识别时，将其调整为按规则需要查询的 `strict` 模式，使进程排除规则能够生效。

## 升级后需要重新应用脚本

1. 退出旧程序，安装对应架构的新版本。
2. 打开“Clash 接入”，粘贴当前完整扩展脚本，生成并复制新脚本。程序会保留原有自定义逻辑。
3. 在 Clash 当前订阅中替换扩展脚本，保存并重新应用配置。仅升级程序不会更新已粘贴的脚本。
4. 确认 Host2VMRelay 已连接虚拟机，再尝试连接虚拟机中的 VPN，检查是否仍受启动顺序影响。

此修复依赖 Clash 正确识别 VMware NAT 进程，且原有分流能够访问 VPN 接入地址。其他虚拟化软件和无法识别来源的网络转发方式需要单独验证。

安装版需要对应架构的 .NET 8 桌面运行时，便携包包含运行时。虚拟机如再次请求辅助程序的执行授权，请核对文件后允许执行。

## 验证范围

新增真实 Mihomo 内核测试，检查 NAT 进程的 TCP、UDP 和域名请求是否沿用原有策略，同时确认宿主机请求仍经过虚拟机。脚本检查覆盖 IPv4、IPv6、旧脚本更新和重复应用。

公司 VPN 的实际登录仍需在用户环境中验收，自动测试不代替真实账户登录。
