# Host2VMRelay v0.7.0

新增 VMware NAT 网络稳定性修复与 VPN 网关 DNS 例外，处理切换 Clash TUN 后 SSH 仍连接、内网却长时间不可用的场景。

## 更新内容

- “Clash 接入”可检查 VMware `.vmx`，在虚拟机完全关机后关闭 NAT 网络状态传播，避免宿主机 TUN 切换触发虚拟机 NAT 网卡断链、删除默认路由。修改前备份，拒绝修改运行中、挂起或格式异常的配置。
- 尊重 Clash 覆写配置中的精确域名真实 DNS 例外，让其优先于内网 Fake-IP 规则，避免内网后缀规则同时把 VPN 登录网关变成 Fake-IP；保留原有自定义脚本和 TUN 界面设置。
- 路由诊断明确区分 SSH 连接与虚拟机出口/VPN 的实际可用性。
- 新增显式现场 TUN 切换测试，测量真实 HTTPS 请求，失败即停止，记录 TUN 创建时间与请求恢复时间。

## 实测与时限

在 Windows + VMware NAT + 虚拟机 VPN 环境，修复前切换 TUN 会使 NAT 网卡断链约 10 秒，随后还需等待 VPN 恢复。修复并冷启动虚拟机、应用网关 DNS 例外后，连续 5 轮 HTTPS 请求均返回 HTTP 200，TUN 开启完成后的响应时间为 275～484 毫秒，未再观察到网卡断链。

同次实测包含 Clash 创建设备在内的总耗时为 1.8～3.1 秒。因此不承诺从点击 TUN 开关起整个过程小于 1 秒，也不保证第三方 VPN 登录、外部网络恢复或已有会话迁移的时限。

## 升级使用

保留现有配置。遇到 VMware NAT 断链时，在“VMware NAT 稳定性”中选择配置并按说明完全关机后修复；虚拟机重启后重新连接 VPN。若网关属于转发规则的域名后缀，在 Clash 全局扩展覆写配置的 DNS 过滤项中添加网关精确域名真实 IP 例外，重新生成并应用完整扩展脚本。使用规则应用检查和实际网址诊断确认结果，不需要盲目重启 Clash 内核。
