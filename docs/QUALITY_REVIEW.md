# 质量审查记录

审查日期：2026-09-28。基线：v0.6.3。改进版本：v0.6.4，待发布。

## 结论

项目已经将配置、脚本合成、网络转发、会话管理和界面分开。生产网络代码可由跨平台测试程序直接复用，适合继续维护。当前产品定位为个人桌面中继，不能将本次结果解释为服务器级并发认证，也不能凭一次审查认定已达到所有商业发布要求。

## 本次处理的问题

| 问题 | 处理方式 | 验证 |
| --- | --- | --- |
| 转发占满名额后，健康探测也被拒绝 | 分开限制入口与转发名额 | 128 路转发保持打开时探测成功 |
| 接入与关闭存在竞争窗口 | 原子检查关闭状态和登记连接 | 20 轮并发接入及关闭 |
| UDP 注册先检查后插入 | 在同一锁内完成检查和插入 | 256 次并发注册仅接纳 128 次 |
| 探测有效期遗漏串行探测耗时 | 集中定义轮询、超时及有效期 | 检查三秒等待加两次三秒探测的预算，并留余量 |
| 上游错误协议头可能被透传 | 检查版本和保留字段 | 错误输入被拒绝并释放名额 |
| 长日志集中刷新增加界面工作量 | 同时限制批次条数和字符数 | 长消息洪泛仍受字符预算约束 |
| 查看日志时新消息打断阅读 | 暂停显示及选择文字时暂停刷新 | 界面操作与布局检查 |
| 定时检查反复编译相同规则 | 按规则文本缓存结果 | 保留配置变更后重新编译路径 |

## 架构与复用边界

- `RelaySession` 负责 SSH 和 UDP 的生命周期，不负责窗口、控件或用户重连意图。
- `RelaySocksServer` 负责协议入口和资源准入。过载明确拒绝，不无限积压连接。
- `DuplexRelay` 负责双向复制及半关闭，`UdpTunnel` 负责有界数据报通道。
- `RelayHealthTiming` 统一时间预算，避免模块各自使用不一致的有效期。
- `PendingLogBuffer` 限制生产端内存和消费端工作量，可脱离 WinForms 测试。
- 日志页移到 `MainForm.Log.cs`，与连接操作、布局、设置分别维护。此拆分仍属于同一窗口类，并非完全解耦的展示层。
- 配置保存仍采用先写入候选值、成功后发布的方式；脚本合成仍只做静态分析，不执行用户代码。

## 测试范围

新增负载检查通过 128 条真实回环连接，双向各发送 32 MiB 数据并逐字节比对，同时检查正常半关闭和资源回收。测试输出建立及传输总耗时、传输耗时的第 95 百分位和进程工作集变化。这些数值包含测试客户端和服务端，不能作为程序独立内存占用或真实 SSH 吞吐指标。

本次本机测试约 0.1 秒完成上述批次，传输耗时的第 95 百分位约为 8 毫秒。短批次只能证明功能和记录基线，不能证明持续高负载能力。完整结果保存在 `artifacts/checks/quality-review/`。

界面在隔离桌面验证，不切换用户桌面、不连接真实虚拟机。原生 200% DPI 下检查五个页面、脚本工作区、键盘导航和控件可达性。启动检查独立于强制截图，避免把截图重绘误当成自然首帧显示。

## 发布前仍需完成

1. 在目标虚拟机上运行长时间真实 SSH/UDP 压力测试，记录 CPU、内存、断线恢复和延迟分布。
2. 人工检查多显示器切换、键盘与屏幕阅读器、高对比度及中文输入法。
3. 验收安装、连续升级、取消和失败恢复，以及不同安全软件下的启动耗时。
4. 建立签名和发行物来源验证流程。当前程序与安装包未签名。

本次不替换已发布的 v0.6.3。候选包和自动检查结果需要与具体提交对应，发布时继续要求 Windows 和网络检查全部成功。
