# 转发内核的演进方案

日期：2026-09-28。状态：设计完成，尚未替换现有 SSH.NET 转发实现。

## 决策

采用与 Clash/Mihomo 相同类型的并发模型：由 Go 运行时调度轻量任务，网络等待不独占每条连接对应的操作系统线程。保留 .NET 界面、配置管理和已有操作习惯，将 SSH 转发数据通道放到职责明确的独立组件中。使用成熟 SSH 库处理加密、认证、通道复用和流量控制，不自行实现 SSH 协议。

这是一项后续内核改造，不能把当前连接上限设置的完成理解为内核已经迁移。

## 为什么不直接替换为 Mihomo 的 SSH 节点

[Mihomo 的 SSH 出站实现](https://github.com/MetaCubeX/mihomo/blob/Meta/adapter/outbound/ssh.go) 已支持密码、密钥和主机公钥匹配，并通过 SSH 客户端打开目标 TCP 通道。但该出站明确声明 UDP 为 false，不能直接保留本项目现有的 UDP 桥接能力。缺少 host-key 配置时，它使用忽略主机公钥的回调；迁移必须保持本项目的首次信任及后续强校验，不沿用这一默认行为。

直接让用户已有的 Mihomo 处理 SSH 还有独立场景价值，但会改变凭据存放、核心配置生效、连接生命周期和独立 SOCKS 服务的边界。嵌入整个 Mihomo 内核会扩大包体、配置和发行维护范围，其许可证为 GPL-3.0。当前不复制其源码，也不把修改用户 Clash 的认证配置作为默认迁移方式。

## 组件分工

- .NET 界面：配置与当前用户凭据加密、首次指纹确认、连接意图、状态展示、日志和 Clash 规则生成。
- Go 转发组件：SSH 认证与连接复用、TCP 双向转发、健康探测、取消和资源回收；最终统一管理现有 UDP 组件。
- 虚拟机 Python 组件：继续执行现有 UDP 套接字和域名解析任务，无需安装常驻服务。
- Clash/Mihomo：继续负责匹配和路由，原有回退行为保持。

Go goroutine 并非操作系统线程，运行时会把大量 goroutine 调度到线程上；可参考 [Go 官方说明](https://go.dev/doc/faq#goroutines)。同步风格的 Go 网络调用不应与当前 SSH.NET 的阻塞线程路径混为一谈。进程线程数仍会变化，不能承诺固定线程数或无资源开销。

## 接口与生命周期要求

1. 控制消息有版本号、请求编号、长度上限和超时。凭据经父子进程管道传递，不进入命令行、日志或临时明文配置。
2. 所有监听只绑定本机回环地址。数据接口必须有父进程限定的认证或句柄传递机制，不能留下无认证管理接口。
3. 首次连接报告主机指纹，界面确认后才继续认证；后续指纹不符立即失败。
4. 父进程退出或控制管道关闭时，子进程关闭 SSH、全部 TCP 通道和 UDP 组件。旧连接的异步结果不得发布到新连接。
5. 断线重连仍由一个明确的所有者控制，避免界面和内核各自重连。正常 TCP 半关闭继续允许反向响应。
6. 默认准入上限 512，可配置 64～2048；保留过载拒绝、健康探测容量和共享 UDP 字节预算。
7. Windows x64、x86、ARM64 分别构建和打包，校验组件版本与哈希。不能靠关闭防护或内存加载规避发行验证。

## 完成标准

- 使用临时本地 SSH 服务和隔离测试账号，完整测量 512/2048 条 SSH 转发的建立时间、线程、工作集、CPU、吞吐和尾延迟。
- 覆盖密码、普通及加密密钥、拒绝首次信任、指纹变化、认证超时和取消。
- 覆盖上下行、半关闭、慢消费者、重连、虚拟机退出、控制组件崩溃及父进程退出。
- TCP 与 UDP 的健康和回退独立验证；不能以 TCP 成功代替 UDP 验收。
- 保留旧实现用于结果对照。新路径通过真实 SSH 集成和持续负载测试后才切换默认实现，并移除不再需要的旧依赖。
